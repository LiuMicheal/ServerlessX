# Documentation guide

Use the documents in this order:

1. [Getting started](getting-started/README.md) for the command lifecycle.
2. [Profiles](concepts/profiles.md) for capability and maturity semantics.
3. [Hardware profiles](how-to/hardware-profiles.md) before considering CUDA,
   RDMA, or the PhOS lab.
4. [CLI reference](reference/cli.md) for stable command shapes.
5. [Research lineage](research/lineage.md) and
   [open-source roadmap](research/open-source-roadmap.md) for context.
6. [Bootstrap decisions](research/bootstrap-decisions.md) for the choices made
   before the first private push.

Documentation describes the boundary that the code and profile declarations
actually support. When evidence and prose disagree, the narrower claim wins
until the evidence or declaration is corrected.
