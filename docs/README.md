# Documentation guide

Use the documents in this order:

1. [Getting started](getting-started/README.md) for the command lifecycle.
2. [Architecture](concepts/architecture.md) for language and ownership layers.
3. [Profiles](concepts/profiles.md) for capability and maturity semantics.
4. [Hardware profiles](how-to/hardware-profiles.md) before considering CUDA,
   RDMA, or the PhOS lab.
5. [CLI reference](reference/cli.md) for stable command shapes.
6. [Research lineage](research/lineage.md) and
   [open-source roadmap](research/open-source-roadmap.md) for context.
7. [Discussion and action record](research/discussion-and-action-record-2026-08-07.md)
   for the decisions and work through the native-core import.

Documentation describes the boundary that the code and profile declarations
actually support. When evidence and prose disagree, the narrower claim wins
until the evidence or declaration is corrected.
